## Checked and clean

- **Migration header vs `Up()`/`Down()`** (`InitialCreate.cs:1-35` vs `:49-184`): every column with its store type and
  nullability (`timestamptz` in the header and `timestamp with time zone` in `Up()` are the same type); `xmin xid`
  correctly described as listed by EF but not created; `pk_employees`, `pk_tasks`; both FKs with
  `ReferentialAction.Restrict`; all four indexes; all four CHECK names; the trigger created by raw SQL at the end of
  `Up()` (`:142-170`, after the last `CreateIndex`) and dropped at the start of `Down()` (`:176-177`); all six seed
  rows, with the creator → assignee direction and the statuses matching `InsertData` (`:105-117`). "generated by dotnet ef
  10.0.12" matches `ProductVersion` "10.0.12" in the Designer and the snapshot.
- **Trigger SQL comments** (`InitialCreate.cs:149-150,157`): identical to spec §11. The claim that an unknown assignee
  leaves `assignee_active` NULL, so the FK reports it, is proven by `Insert_TaskForUnknownAssignee_RejectedByForeignKeyNotBR3Trigger`.
  `:141` correctly cites spec §11 and ADR 0009.
- **`TaskItemConfiguration` docs** (`:10-39`): name every object the Fluent calls create (`pk_tasks`, 2 FKs, 3
  indexes, 4 CHECKs) with a reason for each, contain no phantom entries, place the trigger in the migration and not
  the model (the spec §11 requirement), and explain the `xmin` token. "EF adds no separate index" for the assignee FK
  is true: neither the migration, the Designer nor the snapshot has an `IX_tasks_assignee_id`.
- **`EmployeeConfiguration` docs**: `pk_employees` and `ux_employees_email` named, the seed described, the reason for
  having no concurrency token given (matches spec §10). Only exception: the index "why" (C04).

  **`TaskManagementDbContextFactory`** remarks (placeholder connection, `--connection` for real databases) match
  the code and spec §13.

  `KeyNotFoundException` is service-only) and the inner-exception constructor's only caller

  line (`Employee.cs:46-58`, `TaskItem.cs:73-101`, `:126-136`), including the 200/254 limits and the
  BR5/BR3/BR2 and BR4 conditions.
